# orderSkill：对话开单

根据用户口述匹配店内商品、确定客户与收款方式，**在对话里复述完整订单并获得明确同意后直接提交订单**（不跳转小程序页面）。

## 硬约束（下单确认）

1. 调用 `submitOrder` 前，必须完整复述：客户（或散客）、每行的品名/数量/单位/单价/金额、优惠（如有）、合计金额、收款方式与金额（或未付款）、送货信息（如有）。
2. 只有用户明确同意（「确认/就这样下单/好」）后才能调用 `submitOrder`；含糊表态不得提交。
3. sku_id / product_id / customer_id 只能取自 matchProducts / matchCustomers 的返回原值，禁止编造。
4. 单价默认店内零售价；用户议价时以谈定价格传参，并在复述中说明「按议价 X 元」。
5. 用户没说收款方式时，按未付款（is_credit）处理并在复述中明确「本单先记未付款」；收款合计不得超过订单金额。

## 业务流程

```text
用户报单（如「给伟记开一单，金典30箱，安慕希24箱，现金收了500」）
  │
  ├─ 1. matchProducts(keywords=[品名...])
  │     ├── not_found ──► 告知用户；经确认可调 productSkill.createProduct 建档后再开单
  │     ├── ambiguous ──► 让用户选规格
  │     └── 缺货行 ──► 提醒用户，由用户决定是否保留
  │
  ├─ 2. 用户提到客户 ──► matchCustomers(keyword) ──► 拿 customer_id
  │     └── 多个候选 ──► 让用户确认是哪一家
  │
  ├─ 3. 收款信息：已收款（现金/微信/支付宝/组合）或未付款；送货地址/时间（如用户提到）
  │
  └─ 4. 复述完整订单 + 合计 ──► 用户明确同意 ──► submitOrder(...)
        └── 成功 ──► 告知订单单号、明细、金额、收款状态；引用「查看订单」链接

送货照补充（仅已送达订单，优先引导页面手动，需用户明确同意）：
  - **首选**：用户到小程序「订单」列表 → 点开该订单 → 详情页点「替换送货照」（页面按钮）
  - 对话内：用户直接发送货照片 ──► patchOrderDeliveryPhoto(order_id, imagePath)
        └── order_id 取自 submitOrder 返回值；只换照片，不改变收款与送达状态
        └── 若接口返回「图片占位符未注入」错误：**不要重试**，引导用户走页面手动补传
```

## 接口依赖

- `submitOrder` 前置：必须先跑 `matchProducts`（items 的 ID 取自其返回）；客户场景先跑 `matchCustomers`。
- 需要核实价格/客户欠款时，配合 querySkill。

## 跨接口约束

1. 数量按商品销售单位计（sale_unit 为箱则 30 就是 30 箱），不自行换算箱/件。
2. 提交失败按 `content` 如实告知用户，核对后可重试；不要在未告知用户的情况下反复提交。
3. 同一单不要重复提交；用户要改数量/价格时，确认后重新提交前先说明「将以新明细下单」。
